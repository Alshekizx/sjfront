The **Law Learning Platform** will be a complete, professional, subscription-based **web learning platform for law students**, with this project focusing specifically on the **student-facing website and authenticated student account experience**, built entirely with **React.js**. The administration dashboard should **not** be included in this website because it will be developed separately as a different React.js application with its own domain and admin interface. The student website will use **Supabase** for authentication, PostgreSQL database management, user profiles, subscriptions, learning progress, bookmarks, notifications, content access and secure data services, while **Paystack** will handle online payments and **Supabase Edge Functions** will securely manage payment initialization, verification and webhooks. The entire frontend should have a highly polished, modern, professional **legal-education aesthetic**, using the supplied law logo as the primary brand identity and using a **light background as the default theme**. The visual design should use a clean off-white/light-gray page background, white content cards, deep legal navy as the primary brand colour, subtle gold accents, dark professional typography, generous spacing, soft borders, restrained shadows, rounded cards and clear visual hierarchy. The interface should feel like a premium online law school rather than a basic course website, with excellent responsiveness across desktop, tablet and mobile browsers, smooth transitions, loading states, empty states, error states, confirmation dialogs, skeleton loaders, tooltips, breadcrumbs, progress indicators, badges, dropdowns, tabs, drawers and other professional UI components. The **top navigation should be elaborate and comprehensive**, with the logo and platform name on the left, navigation sections such as **Home, Learn, Academic Levels, Courses, Practice, Case Law, Resources and About**, while the right side should contain **Search, Notifications, Help/Support and the authenticated user's profile/avatar menu**. The navigation should intelligently change depending on whether the user is logged in, with public navigation available to visitors and a personalised learning navigation available to authenticated students. The **Learn** section should provide access to the student's active courses and recently accessed topics, **Academic Levels** should display 100 Level through 500 Level with subscription and locked/unlocked states, **Courses** should allow students to browse authorised courses, **Practice** should provide access to practice questions and examinations, **Case Law** should provide searchable case resources available to the student, **Resources** should provide authorised learning materials, and **About** should contain information about the platform, its purpose and educational approach. The website should also include a prominent global search experience capable of searching courses, topics, notes, cases, videos and practice questions that the current user is authorised to access, with filters such as level, course, content type and topic. Public pages should include a professional **Home/Landing Page**, About page, Academic Levels page, Pricing/Subscription page, Contact/Support page, FAQ, Login, Sign Up, Forgot Password, Reset Password, Terms of Service and Privacy Policy. The landing page should clearly explain what the platform offers, display the five academic levels, explain the subscription model, highlight learning features such as notes, videos, case law, practice questions and examinations, explain the 3-day free trial, provide clear calls-to-action such as **Start Free Trial, Explore Levels and Sign In**, and present the platform as a structured digital learning environment for law students. The **Sign Up experience should be comprehensive and professional**, collecting the student's full name, email address, phone number where required, password, university/institution, current academic level and acceptance of the platform's terms and privacy policy, with proper validation, password-strength feedback, duplicate-email handling, verification-email flow and clear success/error messages. After registration, the user should receive the **3-day free trial**, with the account storing the trial start and expiry dates in Supabase. The student should then enter a complete **personalised Student Dashboard**, which becomes the central hub of the authenticated website. The dashboard should display a personalised greeting, profile information, trial or subscription status, subscription expiry warnings, active academic levels, recently accessed courses, continue-learning cards, overall learning progress, completed topics, upcoming examinations, practice performance, bookmarked resources, recent activity, notifications and useful quick-action buttons. The dashboard should clearly distinguish between **active subscriptions, trial access, expired subscriptions and locked levels**, allowing the student to immediately understand what they can access. The **Academic Levels page** should display 100 Level, 200 Level, 300 Level, 400 Level and 500 Level as professionally designed cards, with each card showing the level name, description, number of courses, subscription price, subscription status, progress where applicable and an appropriate action such as **View Level, Continue Learning, Subscribe or Renew**. Each level must operate as an independent subscription package, so purchasing 100 Level gives access only to 100 Level, purchasing 300 Level gives access only to 300 Level, and purchasing another level requires another payment. The system must enforce this access at the backend/database level through **Supabase Row Level Security and subscription entitlement checks**, meaning students cannot unlock another level by changing URLs, manipulating browser storage, directly requesting database records or attempting to bypass frontend restrictions. The **Level Details page** should provide a complete overview of the selected academic level, including its description, courses, learning objectives, number of resources, subscription information, active/locked status, progress and a clear subscription or learning CTA. Once authorised, students should be able to enter the **Course Listing page**, where all courses belonging to that level are presented using professional course cards containing course title, description, course code where applicable, thumbnail, number of topics, progress percentage, completion status and continue/start buttons. Each **Course Details page** should provide a complete course overview with course description, learning objectives, instructor information where applicable, progress, topic list, course resources, videos, cases, practice questions and examinations. The **Topic Learning page** should provide a structured learning interface with a left or collapsible course navigation panel, topic list, completion indicators, previous/next navigation and a main content area where the student can study the selected topic. The **Notes Reader** should be particularly polished, allowing students to read comprehensive law notes directly in the browser with professional typography, headings, subheadings, tables, lists, highlighted legal terms, definitions, examples, key points, case references and related resources. Students should be able to adjust reading preferences such as font size where appropriate, bookmark content, mark a topic as complete, navigate between topics and resume from their previous position. Important legal terms should be presented with interactive definitions or information popovers where applicable. The **Video Learning page** should contain a professional video player with play/pause, seeking, volume, fullscreen, playback speed, progress tracking, resume position and related notes/topics, with video completion contributing to the student's learning progress. The **Case Law section** should provide a professional searchable interface for relevant cases, with each case page containing the case name, citation, year, court, facts, legal issue, decision, legal principle, simple explanation, significance and relationship to the current topic, allowing students to bookmark cases and return to them later. The **Practice section** should provide practice categories including MCQs, past questions, problem questions, scenario-based questions, essay questions and mock examinations, with filters for academic level, course, topic and difficulty. The question interface should provide clear questions, answer options where applicable, navigation, question numbering, progress indicators, flag-for-review functionality and submission controls. After submission, the system should provide **results and explanations**, including score, percentage, correct answers, incorrect answers, explanations, relevant legal principles and model answers where applicable. The **Mock Examination system** should provide timed examinations with a professional examination interface, countdown timer, automatic saving of answers, question navigation, answered/unanswered indicators, flagged questions, confirmation before submission and a detailed results page showing performance and answer review. The student's **Progress page** should provide a comprehensive learning analytics view showing overall progress, level progress, course completion, topic completion, practice-question performance, examination history, scores, accuracy and recent learning activity. The platform should also include a complete **My Library/Bookmarks section**, allowing students to save notes, cases, videos, courses, topics and other authorised resources for quick access. The **Notifications centre** should display payment confirmations, subscription expiry reminders, new learning content, examination announcements, platform announcements and other relevant student notifications, with unread indicators and notification detail views. The authenticated user's **Account Management area should be extremely complete and professional**, accessible through the profile/avatar menu and a dedicated account section. It should contain **Profile, Personal Information, Academic Information, My Subscriptions, Payment History, Learning Progress, Bookmarks, Notifications, Security, Password & Login, Preferences, Help & Support, Terms & Privacy and Logout**. The Profile page should allow users to manage their name, profile photo, phone number, university/institution and academic level. The Academic Information section should manage educational information relevant to the student's learning experience. The **My Subscriptions page** should clearly display every level the student has purchased, subscription status, start date, expiry date, price paid, payment reference and available actions such as Continue Learning, Renew or Subscribe to Another Level. The **Payment History page** should display transaction references, purchased level, amount, payment status, payment date and payment details. The Security section should allow password changes, session management and other appropriate account-security controls. The Preferences section should manage notification preferences and other non-sensitive user preferences. The Help & Support area should provide FAQs, contact/support options and relevant assistance. The profile dropdown in the top navigation should provide quick access to **Dashboard, My Learning, My Subscriptions, Progress, Bookmarks, Notifications, Account Settings and Logout**. The payment experience should be integrated directly into the website through **Paystack**, with a professional subscription checkout page showing the selected level, price, subscription duration, benefits, payment information and secure-payment messaging. Payment initialization and verification must happen securely through **Supabase Edge Functions**, with the Paystack secret key never exposed in the React.js frontend. Once payment is successfully verified, the student's subscription record should be created or updated in Supabase, the appropriate level entitlement should immediately become active and the student should be redirected to a professional **Payment Success page** showing the transaction reference, purchased level, amount, subscription period and **Start Learning** button. Failed or cancelled payments should have dedicated error states with retry functionality, while pending transactions should remain pending until properly verified. The platform should automatically detect expiring and expired subscriptions and clearly communicate the status to the student, while expired level access should become locked until the student renews. The **3-day trial** should be prominently but professionally communicated throughout the authenticated experience, showing the remaining trial period and encouraging the student to subscribe before access expires. The frontend should include comprehensive **loading, empty, error, success and confirmation states** for all major operations, including login, registration, payment, subscription loading, course loading, video loading, notes loading, practice submission, examination submission, profile updates and account actions. All pages should use a consistent design system with reusable React components, responsive layouts, accessible form controls, consistent buttons, cards, modals, dropdowns, tabs, badges, alerts, breadcrumbs, pagination where necessary and professional typography. The default appearance must be **light mode**, with an off-white/light-gray overall background and white cards and content surfaces; a dark mode may be added later as an optional preference but should not be the default. The platform should be designed mobile-first and responsive, but because it is a website rather than a mobile application, the desktop experience should receive particular attention, including a sophisticated top navigation, spacious content layouts, sidebars for learning pages, multi-column dashboards, tables for account/payment information and professional desktop examination interfaces. The **student-facing React.js application should be completely independent from the administration dashboard**: there should be no admin management screens, admin sidebar, content-management pages or administrative controls inside this project. The separate admin application will handle content creation, course management, users, payments, subscriptions, questions, examinations, notifications, system settings and other administrative functions. This frontend should instead focus entirely on delivering the **best possible student experience and complete user account management system**, with Supabase providing the secure backend connection. The complete student journey should therefore be **Visit Website → Explore Platform → Sign Up → Verify Account → Receive 3-Day Free Trial → Student Dashboard → Explore Academic Levels → Select Level → Subscribe/Unlock Level → Pay Through Paystack → Secure Payment Verification → Level Unlocked → Browse Courses → Select Course → Study Topics → Read Notes / Watch Videos / Study Cases → Bookmark Resources → Practise Questions → Take Mock Exams → Receive Results → Track Progress → Manage Subscription and Account**, creating a polished, professional and scalable **React.js web-based digital law school** focused entirely on learning, subscriptions, student accounts and the overall student experience.
